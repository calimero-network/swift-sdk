A session opened for an app's package may not create an organization, mint or
accept an invite, approve a mero-tee release, upgrade an app instance or open
outbound hosts on its own. The app asks the node, and the person decides on
the node's own consent page, with their passkey. `client.consent` is the
helper for that (the Swift twin of mero-js `client.consent.request / begin /
resume / wait`).

| Method | Route | |
| --- | --- | --- |
| `consent.request(_ ask:, returnTo:)` → `ConsentStarted` | `POST /consent/requests` (sealed) | `{ requestId, url, code, expiresAt }`; refuses a `code` that is not the page's (`CONSENT_CODE_MISMATCH`) |
| `consent.result(requestId:)` → `ConsentDecision` | `GET /consent/{id}/result` (sealed, the same account) | the decision now |
| `consent.resume(url:)` → `ConsentDecision?` | the same | the decision for a `returnTo?request_id=…&result=…` URL, `nil` for any other URL |
| `consent.wait(requestId:timeout:interval:)` → `ConsentDecision` | the same, polled | until decided, or `pending` once `timeout` passes |
| `ConsentLauncher.begin(client:ask:callback:…)` (MeroKitUI) → `ConsentDecision` | all of the above | the page in `ASWebAuthenticationSession`, or the browser plus `wait` |

## What to ask, and what comes back

| `ConsentAsk` | `outcome` once approved |
| --- | --- |
| `.createOrg(name:)` | `.orgCreated(orgId:)`, `decision.orgId` |
| `.createInvite(org:role:teams:ttlSecs:uses:allApps:)` | `.inviteCreated(token:)`, `decision.inviteToken` |
| `.acceptInvite(token:)` | `.inviteAccepted(org:)`, `decision.joinedOrg` |
| `.release(scope:version:withdraw:)`, `.upgrade(app:toVersion:)`, `.outbound(scope:package:prefixes:)` | none |

A `ConsentDecision` has `requestId`, `kind` (`ConsentKind`, which also holds
kinds newer than the SDK), `status` (`pending`, `approved`, `declined`),
`decidedAt` and `outcome`. An approved `createOrg`, `createInvite` or
`acceptInvite` without its outcome is refused as a protocol violation.

An invite token is a bearer credential. `ConsentAsk`, `ConsentOutcome` and
`ConsentDecision` print it as `<redacted>` in their descriptions, debug
descriptions and mirrors (`print`, `dump`, string interpolation), and no error
carries it. Read it only from `decision.inviteToken`, and don't log it.

## `returnTo`: a universal link

The node takes a `returnTo` only on the app package's own frontend origin or an
origin its signed manifest names (`links.frontend`, `frontendAliases`). For a
native app that is a universal link on such an https origin, served with the
app in its `apple-app-site-association` and listed in the app's Associated
Domains:

```swift
let callback = CloudCallback.https(host: "chat.example", path: "/consent")
```

## In the app

```swift
import MeroKitUI

let decision = try await ConsentLauncher.begin(
    client: cloud, ask: .createOrg(name: "Acme"), callback: callback,
    confirm: { started in await showCode(started.code) })   // false: don't open the page
if let org = decision.orgId { open(org) }
```

`MeroAppSession.requestConsent(_ ask:)` does the same with the session's
`callback`, keeps the answer in `consentDecision` (and `consentResult`), and
bumps `revision` when an organization was created or joined.

- **iOS 17.4+ / macOS 14.4+.** The page opens in `ASWebAuthenticationSession`
  with the `.https(host:path:)` callback, and the URL the page sends the person
  back to is resumed.
- **Older systems.** `ASWebAuthenticationSession` takes no https callback
  there, so the page opens in the browser and `begin` polls the result
  (`wait`) until the request expires. The page sends the person back through
  the universal link, which arrives in `onOpenURL`; hand it to
  `session.handle(url)` (or `client.consent.resume(url:)`), which reads the
  node's decision.

```swift
.onOpenURL { url in Task { await session.handle(url) } }
```

The query on the return URL is a hint only: `resume` always reads the decision
from the node, and an app should check `requestId` is one it started. A sheet
dismissed before a decision throws `WebAuthenticationCancelled`; the request
stays on the node until it expires (10 minutes).

## Without MeroKitUI

```swift
let started = try await cloud.consent.request(.acceptInvite(token: token), returnTo: callback.url)
show(started.code)                       // the page shows the same code
open(URL(string: started.url)!)          // the node's own page
let decision = try await cloud.consent.wait(requestId: started.requestId)
```

`openConsentPage`, `waitForConsent` and `ConsentRequest` still work for
`release`, `upgrade` and `outbound`. They don't know the newer kinds, and they
read results through the generated types, which don't have them yet either.
