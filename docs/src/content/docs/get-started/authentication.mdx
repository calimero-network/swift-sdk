There is no auth service: the node registers passkeys, mints sessions and
checks API keys, all inside the sealed channel.

| Who | Credential | Lifetime |
| --- | --- | --- |
| A person | a passkey, which opens a session `v2.…` | 15 minutes, refresh token `rt_…` 30 days |
| A service | an API key `cal_…` (`useApiKey`) | up to 365 days |

## Passkeys

- `signUp(passkey, name:)`: `POST /auth/passkey/register/{begin,finish}`.
- `signIn(passkey)`: `POST /auth/passkey/login/{begin,finish}`. Begin and finish reach the same node.
- `PasskeyProvider` is what holds the key: `PlatformPasskey` (MeroKitUI,
  `ASAuthorizationPlatformPublicKeyCredentialProvider`) or `SoftPasskey`
  (software, development clusters; the same JSON as `meroctl --dev-passkey`).
- A dismissed prompt throws `PasskeyCancelled`; in a confirmation it surfaces as `ConfirmCancelled`.

## Sessions

`CalimeroClient` holds the session (`useSession`, `session`). `onSessionChange`
reports every new one (sign-in, refresh, sign-out) so a mobile app can keep it
in the Keychain (`KeychainCloudSessionStore`); `MeroClient` does this for you.

- A `401` to a request that carried a session triggers **one** refresh
  (`POST /auth/refresh`), shared by every request that needs it at that moment:
  a refresh token is used once, and reusing one revokes the session. The
  request is then repeated. A refused refresh surfaces as `LoginRequired`.
- `421 WRONG_NODE`: this node's release may not serve the account. The client
  moves to the next node in `nodes` and repeats the request (a refresh tries
  each node once; a sign-in is the caller's to repeat).
- `421 NOT_LEADER`: repeated at `details.leaderUrl` when that is one of `nodes`.

## Step-up confirmations

`412 CONFIRM_REQUIRED` asks for a passkey assertion over the exact request:
the `*Confirmed` methods (`callConfirmed`, `postConfirmed`, `deleteOrg`,
`upgradeApp(passkey:)`, `approveRelease`, …) answer it with the passkey you
give them and send the request once more with `confirm`.

## Approvals happen on the node's consent page

Release, upgrade and outbound approvals are never made inside an app:

```swift
let started = try await client.requestConsent(upgradeConsent(app: app, toVersion: "1.2.0", returnTo: "myapp://consent"))
// open started.url in the system browser (MeroClient.requestConsent uses ASWebAuthenticationSession)
let result = try await client.consentResult(started.requestId)
```
